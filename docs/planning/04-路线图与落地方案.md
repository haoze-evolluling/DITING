# 谛听安卓端功能扩展规划 · 04 路线图与落地方案

> 本文把 `03` 的功能清单排成分期路线图，并给出 Rust / Flutter / Kotlin 三层的改造落点、数据模型、配置文档、
> 测试与风险。目标是让规划“可执行、可估、可验收”。当前安卓版本基线：**2.4.2+20402**。
> 工程红线（`AGENTS.md`）：单文件 ≤ 600 行；逻辑进 Rust 单一实现；提交用中文 Conventional Commits。

## 1. 分期路线图

> 版本号仅作建议（安卓为独立产品线，`-g android` 单独升级）。每阶段以“可独立发布、可回滚”为原则。

### 阶段 0 · 地基（1 个迭代，约 2–3 周）→ `2.5.0`

- **目标**：把“扩展底座”铺好，让后续功能低摩擦接入。
- **功能**：K9（事件总线 + ABI 版本）、K10（配置文档规范）、K3（`diting-schedule-core` 纯函数 + 单测）、
  K4（规则命中计数内核）、A7（引入 WorkManager）、A5（状态广播 + 通知快捷动作）。
- **交付物**：`diting-schedule-core`、`diting-hit-core`（或并入 policy-core）；`AutomationReceiver`（签名权限）；
  `ScheduleController`（Alarm+WM）；通知 action。
- **验收**：interval/daily/cron/window/pause 单测全绿（含 DST/跨天）；WorkManager 任务跨重启生效；
  状态广播结构稳定（schema 冻结）；现有订阅更新回归通过。

### 阶段 1 · 可解释与轻控制（2 个迭代，约 3–5 周）→ `2.6.0`

- **目标**：先解决“为什么被拦 / 一键控制 / 可信可观测”，投入产出比最高。
- **功能**：R1（规则测试）、R2（命中统计+归因）、R3（订阅健康）、R4（临时暂停 + 仅白名单）、
  N4+K2（实时连接视图/flow-core）、U1（健康评分+Advisor）、U2（全局搜索/命令面板）。
- **交付物**：`check_host` JNI、`diting-flow-core`、命中计数落库、`pages/network/flow`、`pages/health`、`global_search`。
- **验收**：规则测试结果与桌面 `/filter/check` 语义一致（用 `diting-corpus` 对照）；flow 视图真机 60fps；
  健康评分覆盖权限/DNS/过滤器/缓存四维；搜索可直达全部二级页与设置项。

### 阶段 2 · 场景与策略（3–4 个迭代，约 6–8 周）→ `2.7.0`

- **目标**：自动化“成面”，网络策略“可编排”。
- **功能**：A1（条件-动作引擎）、A3（Profiles）、A2 上层（timetable A12）、A4（暂停动作）、
  N1+K5（网络 Profile）、N2（条件路由第二输出）、N3（策略组/回退链）、R7（分时规则 + blocked services）、
  A8（Tasker 插件）、A13（场景切换上游/规则组）。
- **交付物**：`diting-netprofile-core`、`policy-core` 决策第二输出、`resolver-core` 策略组、自动化编辑页、
  档案管理、周视图。
- **验收**：5 个典型场景走查通过（到家/会议/游戏/低电/Tasker 联动）；条件路由命中正确率对齐单测；
  切换档案/网络无隧道崩溃；DSL 冲突按优先级/冷却解释可视。

### 阶段 3 · 纵深与生态（3–4 个迭代，约 6–8 周）→ `3.0.0`

- **目标**：隐私套件、协议演进、对外生态、可达性。
- **功能**：K1（safebrowsing/dns64/ratelimit 并入）、U10（隐私套件）、N6（泄漏检测+Captive Portal）、
  N7（DoH3/连接复用）、N8（DNS64 UI）、N9（LAN 客户端/限速）、R6（订阅版本回滚）、R8（别名链复检）、
  A10（本地 HTTP API）、A11（Webhook）、U5/U6（应用报告卡/连接地图）、U7/U8/U9（a11y/i18n/自适应）。
- **验收**：Safe Browsing 命中走 `diting-safebrowsing-core`；IPv6-only 网络可解析；DoH3 与 DoH 结果一致；
  LAN 客户端限速生效；HTTP API 仅 127.0.0.1 + token；三语言 UI 无截断；平板双栏可用。

> 阶段间可并行：例如 U7–U9（体验）、R5/R9、文档属低耦合，择机插入。

## 2. Rust 内核改造清单

### 2.1 现有链接调整（K1）

在 `rust/diting-engine/Cargo.toml` 追加普通依赖（静态并入 `libditing_engine.so`，**不需要** dlopen/C ABI）：

```toml
diting-safebrowsing-core = { path = "../diting-safebrowsing-core" }
diting-dns64-core        = { path = "../diting-dns64-core" }
diting-ratelimit-core    = { path = "../diting-ratelimit-core" }
# 可选：diting-filter-core / diting-rewrite-core / diting-stamp-core / diting-hosts-core
```

> 落地前须逐一核对上述 crate 的 `pub fn` 接口与是否存在 `ffi.rs/payload.rs`（部分为桌面 Go 面设计）。
> 复核 `diting-ipcache-core`、`diting-allowlist-core` 当前归属，避免重复链接。

### 2.2 新增内核（K2–K8）

| crate | 输入/输出（要点） | 归属库 | 备注 |
|---|---|---|---|
| `diting-schedule-core` | `{now, slots[], rules[]}` → `{due,nextDueAt,windowActive}` | kernels（`diting-kernels`） | 纯函数、`now` 注入；抽 `subscription.schedule::Cadence` |
| `diting-hit-core`（或并入 policy） | `rule_id/list_id` 原子计数 + 快照导出 | engine 或 kernels | 分片原子，低开销 |
| `diting-flow-core` | 会话表增删改 + 增量快照 JSON | engine | 消费 connlog/sniffer/ipcache/telemetry |
| `diting-netprofile-core` | `{networkCtx, profiles[]}` → 生效配置引用 | engine | 字段对齐 sing-box |
| `diting-leak-core` / `diting-captive-core` | 指纹探测求值 / 204 探测状态 | kernels | 无网络 I/O，探测在 Kotlin/Dart |
| `diting-rule-version-core` / `diting-response-core` / `diting-services-core` | 版本 diff、别名复检、服务目录 | kernels | 纯函数 |

### 2.3 FFI / JNI 接口草案（示意）

```rust
// 规则测试（引擎侧，JNI 或共享内存 JSON）
fn check_host(host: &str, qtype: u16) -> CheckResult; // {action, rule, list, reason, rewrite}

// 规则命中计数
fn hit_snapshot() -> HitSnapshot; // [{rule_id,list_id,count}]
fn hit_reset();

// 调度求值（UI 侧内核，C ABI + JSON）
fn schedule_evaluate(now_ms: i64, doc_json: &str) -> String;

// 网络 profile 求值
fn netprofile_resolve(ctx_json: &str, profiles_json: &str) -> String;

// 规则版本
fn rule_version_diff(old: &str, new: &str) -> String;
```

所有新增导出须维护 `ABI_VERSION`；Dart 侧仿 `RustBackupCore.instance` 的“缺库硬报错”模式，不写第二套实现。
`diting-kernels/src/lib.rs` 追加 `pub use`，`rust/build_android.py` 自动并入 `libditing_kernels.so`。

## 5. 数据模型与迁移

复用 `diting_database`（sqflite），新增表（建议随 `legacy_schema` 版本迁移，备份分组纳入 `diting-backup-core`）：

```sql
-- 自动化规则 / 档案 / 审计
CREATE TABLE automation_rule(
  id TEXT PRIMARY KEY, name TEXT NOT NULL, enabled INTEGER NOT NULL DEFAULT 1,
  priority INTEGER NOT NULL DEFAULT 100, match TEXT NOT NULL DEFAULT 'all',
  spec_json TEXT NOT NULL, last_run_at INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL);
CREATE TABLE automation_profile(
  id TEXT PRIMARY KEY, name TEXT NOT NULL, payload_json TEXT NOT NULL,
  created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL);
CREATE TABLE automation_event(
  id INTEGER PRIMARY KEY AUTOINCREMENT, ts INTEGER NOT NULL,
  rule_id TEXT, event TEXT NOT NULL, outcome TEXT, detail_json TEXT);

-- 规则命中统计（落库聚合，内存分片计数定期 flush）
CREATE TABLE rule_hit_stat(
  bucket_ts INTEGER NOT NULL, rule_id TEXT NOT NULL, list_id TEXT,
  hits INTEGER NOT NULL DEFAULT 0, PRIMARY KEY(bucket_ts, rule_id));

-- 订阅健康 / 版本
ALTER TABLE subscription_group ADD COLUMN last_status TEXT;   -- ok/unchanged/cached/failed
ALTER TABLE subscription_group ADD COLUMN last_rule_count INTEGER;
CREATE TABLE rule_version(
  id INTEGER PRIMARY KEY AUTOINCREMENT, group_id TEXT NOT NULL,
  hash TEXT NOT NULL, rule_count INTEGER NOT NULL, created_at INTEGER NOT NULL);
```

- `automation_event`、`rule_hit_stat` 纳入 `diting-cleanup-core` 的保留策略，避免无限增长。
- 备份新增分组：`automation.rules`、`automation.profiles`（注意剔除 token/代理密码等密钥字段）。
- 迁移必须可回滚：新增列用 `ADD COLUMN`（SQLite 支持），新表 `IF NOT EXISTS`。

## 6. 配置文档扩展（`diting-*-config-core`）

- **DNS 管线**（`diting-dns-config-core` / `diting-dns-core`）：增 `record_type_block{a,aaaa,https,...}`、
  `ecs_policy{send,strip,preset}`、`rebinding_protection`、`allowlist_only`、`pause_until`、`safe_search{force,engines,ttl}`、
  `bogus_reply_cidrs`、`dns64{enabled,prefix,clat}`。全部进 document 构建 + 校验 + 默认值。
- **路由**（新增 `diting-route-config-core` 或在 `diting-dns-config-core` 内）：`route_rule{app/domain/geosite→upstream_tag/outbound_tag}`、
  `policy_group{type,members,health_check}`、`fallback_chain`。
- **隧道**（`diting-vpn-config-core`）：`kill_switch`、`always_on_hint`、`underlying_network_policy`。
- **网络 profile**（`diting-netprofile-core`）：`profile{network_match, upstream_set, rule_group_states, feature_toggles}`。
- 所有新增字段必须与 Dart 端“缺省即关闭”一致，杜绝“UI 开了引擎不认”。

## 7. 测试与验证策略（按风险分级，避免过度测试）

- **Rust 单测（必做）**：调度（DST/跨天/补跑边界）、命中计数并发、flow 会话过期、netprofile 求值、别名链深度、
  正则预算；用注入时钟与 `diting-corpus` 做行为冻结回归。
- **Dart 单测/Widget**：新增页面状态机、搜索索引、档案切换、健康评分计算；路由目录同步测试。
- **真机 Smoke（关键路径）**：三模式启停、规则测试一致、暂停到期恢复、连接视图刷新、档案切换不崩、WorkManager 跨重启、
  通知 action、磁贴/组件。
- **性能**：包体（新增内核的 `.so` 增量）、内存（flow 会话表上限）、启动耗时、列表滚动帧率。
- **安全**：HTTP API 未授权拒绝、签名权限缺失不可触发、导出不含密钥、自动化不绕过首启协议/VPN 授权。

## 8. 风险登记与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 决策“第二输出”改动 `policy-core` 判定树 | 规则回归面大 | 先做 R1/R2 稳定判定；新字段只增不改；corpus 回归；分阶段灰度 |
| 精确闹钟/Doze 漏跑 | 定时不准 | Alarm + WorkManager 双保险；UI 明示“可能延迟”；`windowSec` 补跑一次 |
| 厂商杀后台 | 定时/事件不触发 | 引导“忽略电池优化”，FGS 兜底，`NeedsApp` 回退 |
| 新增内核包体/内存 | 安装包与占用 | 复用现有依赖（quinn/rustls/smoltcp）；`opt-level="s"`+LTO；flow 表设上限 |
| 对外入口被滥用 | 被第三方控制 VPN | 签名权限 + token + 仅 127.0.0.1 + 默认关闭 + 审计 |
| 配置/迁移不一致 | 升级崩溃或行为漂移 | `diting-*-config-core` 归一 + 迁移脚本 + 回滚方案 |
| 许可证 | 合规 | 按 `02` 的许可矩阵；MPL 文件级隔离；专有仅学交互 |
| 商店政策 | 上架受阻 | 不申请 `USE_EXACT_ALARM`/无障碍；后台定位需声明；VPN 类应用隐私说明 |
