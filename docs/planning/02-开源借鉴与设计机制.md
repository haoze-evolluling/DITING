## 3. 四条主线的关键机制提炼

### 3.1 网络管理：把“判定”升级为“路由决策”
- **决策第二输出**：现有 `policy-core` 输出“允许/阻断”；扩展为同时输出 `upstream_tag / outbound_tag /
  fallback_chain`，即“这个域名/应用该走哪条上游与出口”。这是条件路由、按网络差异化、每应用上游的共同底座。
- **网络上下文来自平台**：Kotlin `ConnectivityManager` 归一出 `network_type / metered / roaming / validated /
  ssid / bssid`，Rust 只消费归一化 profile，字段命名对齐 sing-box，避免自造词。
- **可观测**：`connlog-core`（去重）+ `sniffer-core`（SNI/Host）+ `ipcache-core`（IP→域名）+ `telemetry-core`
  （按 UID 计数）已备齐，缺一张 **flow 会话表内核** 与页面。
- **信任链补全**：DNS 泄漏检测（域名指纹 + 对照配置上游）、Captive Portal（RFC 8910 + `generate_204`，与拦截冲突时临时放行）、
  Kill switch（系统 always-on 引导 + `setBlocking(true)` + 看门狗退避）。

### 3.2 规则管理：从“能拦截”到“可解释、可治理”
- **可解释**：为每条判定返回 `matched_rule / list / reason / rewritten`，与日志“一键解释”打通；按“规则库 + 规则”双键做
  分片原子计数（AdGuard Home `Result.rules[]` 模型）。
- **可治理**：订阅库健康（ok / 304 unchanged / cached / failed）、版本化/diff/回滚、按库单独开关与规则数、拖拽排序、
  冲突与被遮蔽提示（只读解释视图，不改判定树）。
- **可组合**：仅白名单模式、临时暂停、分时拦截、blocked services 预设分组、多格式导入自动识别。
- **健壮性**：正则长度/编译预算（ReDoS 防护）、响应侧 CNAME 别名链复检（默认关、深度≤8）。

### 3.3 自动化：从“三个命令”到“条件-动作场景引擎”
- **统一模型**：`触发器（时间/网络/电量/状态/外部）+ 条件 + 动作 + 冷却/优先级/幂等/补跑`；动作覆盖启停、切模式、
  切档案、切上游、开关规则组/功能、临时暂停、通知、外发。
- **调度内核**：新增 `diting-schedule-core`，把 `diting-subscription-core::schedule` 的 interval/daily 抽成通用
  `Cadence`，扩展 `cron`（5 字段子集）/`window`/`pause`，纯函数、`now` 注入、可单测。
- **平台双保险**：`AlarmManager.setExactAndAllowWhileIdle` 准点 + `WorkManager` 兜底（现仓库明确无 WorkManager）。
- **对外协议**：签名权限广播 + Tasker/Locale 插件（动作/条件/事件）+ 本地 HTTP API（127.0.0.1 + token）+ 出站 Webhook（HMAC）。

### 3.4 体验与内核：补“解释、检索、可视化、自适应”
- **解释优先**：把已有 AI 日志洞察升级为全局 **保护健康评分 + Advisor**（权限/DNS/过滤器/缓存/拦截率/异常 → 下一步建议）。
- **检索优先**：全局搜索/命令面板（跳转 + 动作），承载日益增多的入口。
- **可视化**：应用报告卡、连接地图、Top 拦截排行、时间轴统计。
- **内核杠杆**：桌面已成熟的 `safebrowsing/dns64/ratelimit/filter/rewrite/stamp` 以内核依赖方式静态并入安卓引擎
  （无需新增 dlopen），补齐隐私套件、IPv6-only、LAN 限速等能力。

## 5. 明确“不建议引入”（避免过度设计）

- **不建议**申请 `USE_EXACT_ALARM`（Android 13+ 仅闹钟/日历类可用；DNS 工具应退化为 `SCHEDULE_EXACT_ALARM` 或非精确）。
- **不建议**引入无障碍服务或读取通知内容；“前台应用”用 `UsageStatsManager`。
- **不建议**把 geosite/geoip 大型规则集放进核心（体积与更新成本高，作为可选预设即可）。
- **不建议**让本地 HTTP API 监听 `0.0.0.0`（默认仅 127.0.0.1 + token + 默认关闭）。
- **不建议**为“准点/自动化”牺牲首启协议与 VPN 授权合规（失败走 `NeedsApp` 回退并提示）。
