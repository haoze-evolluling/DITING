# 云控贡献者名单维护说明

本文档说明 DITING 项目赞助者与共建者名单的云控展示机制、数据格式要求及维护更新流程。

---

## 1. 运行机制

名单数据通过 GitHub 仓库远程驱动：
- **配置文件**：根目录下的 `recognition_members.json`。
- **头像资源**：根目录下的 `avatars/` 文件夹。
- **生效方式**：修改配置或新增头像后，直接推送到 GitHub `main` 分支即可对所有客户端动态生效，**无需发布新版本 APP**。
- **缓存策略**：客户端每次进入名单页面时从 GitHub 拉取最新配置，校验通过后原子写入本地缓存；若网络异常或配置校验失败，则优雅降级展示上一次成功的本地缓存。

---

## 2. 配置文件格式规范 (`recognition_members.json`)

根目录的 `recognition_members.json` 采用 JSON 格式，必须包含以下根字段：

- `version` (整数)：配置版本号，每次更新名单建议递增。
- `sponsors` (数组)：赞助者列表。
- `coBuilders` (数组)：共建者列表。

### 成员项字段定义

每个数组元素为一个 JSON 对象：

| 字段名 | 类型 | 是否必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `name` | String | 是 | 成员昵称或展示名称，不可为空，同一数组内不得重复 |
| `avatarFileName` | String | 否 | 自定义头像文件名。若缺省或为空，客户端自动使用内置默认头像 `default_avatar.png` |

### 排序与约束规则

1. **展示顺序**：前端渲染顺序与 JSON 数组元素顺序完全一致（赞助者按赞助时间排序，共建者按约定顺序展示）。
2. **唯一性**：同一数组内的 `name` 及 `avatarFileName`（非空时）不得重复。

---

## 3. 头像资源规范 (`avatars/`)

- **命名规范**：文件名必须严格匹配小写正则：`^[a-z0-9_]+_avatar\.jpg$`，例如 `alone_avatar.jpg`。
- **文件格式**：统一为 JPG 格式图片（内置缺省头像为 `default_avatar.png`）。
- **尺寸与体积**：推荐正方形图片（例如 256x256 或 512x512），经过适当压缩（单张控制在 100KB 以内），确保加载性能。
